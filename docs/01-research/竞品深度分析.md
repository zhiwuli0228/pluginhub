## 0. 执行摘要（先看结论）

1. **低代码画布路线已被市场证伪，运行时管理路线正在上升。** Flowise 于 2026-07-29 宣布关停、08-13 归档、08-31 EOL，官方给出的理由是"开发者转向 Claude Code / OpenClaw 等编码 Agent，僵化的低代码工作流在复杂度上很快触顶"【官方】。同期 OpenClaw 达 **394,811 Star**，成为现象级项目【API实测】。市场重心从"拖拽搭流程"转向"管理真正跑起来的 Agent 与插件进程"。

2. **协议层解决"描述与通信"，但完全没有解决"运行时管理"。** MCP `mcpServers` 配置与 A2A Agent Card 均**没有**进程启停/重启策略、资源限制（CPU/内存/并发）、健康检查、端口仲裁、成本计量、日志聚合字段【规范】。这是四维度中"进程管理"的系统性空白。

3. **四个维度上没有一家全覆盖。** Dify 在插件发现与进程隔离上最强（Go plugin daemon + Marketplace 签名校验），LangGraph Studio 在状态可视化上最强（图结构 + 节点中间态 + 时间旅行），OpenClaw 在本地进程守护与插件生态上最强（systemd/launchd + ClawHub + 热重载），BeeAI 在协议标准化上最规范（ACP→A2A 迁移）。**但没有任何一家把"发现—注册—进程—数据"做成统一控制平面。**

4. **描述格式严重碎片化。** 六种工具使用了至少六套互不兼容的格式：`mcpServers` JSON、`langgraph.json`、`.chatflow` JSON、`manifest.yaml` + DSL `.yml`、`A2A Agent Card`、`openclaw.plugin.json` + `package.json#openclaw` + `SKILL.md` frontmatter。字段定义各自为政，转换成本由用户承担。

5. **托管商业模式已有失败案例。** MCP 托管商 Smithery 于 2026-10-31 关停代理/API/CLI（仅留公开注册表），mcp.run 已停运【社区，需带时点】。单纯做"注册表/托管"难以成立，必须与运行时治理绑定。

6. **可复用设计模式已浮现**：独立插件守护进程、Manifest 声明式能力注册、控制平面 + 多客户端、checkpointer 状态恢复、事件总线 + OTel 观测、well-known 发现端点。详见 §3.1。

## 2. 技术实现摘要

### 2.1 插件 / Agent 描述文件格式与字段定义

| 工具 | 格式与位置 | 关键字段 | 备注 |
|---|---|---|---|
| **MCP** | JSON：`mcpServers`（各客户端路径不同：Claude Desktop `claude_desktop_config.json`、Claude Code 三级 scope） | `command`、`args`、`env`、`cwd`、`url`、`transport`(stdio/sse/http)、`headers`、`type` | Inspector 专有扩展：`protocolEra`、`roots`、`metadata`、`connectionTimeout`、`oauth{}` |
| **MCP Registry** | `server.json`【规范】 | `$schema`、`name`(反向DNS)、`title`、`description`(1–100)、`version`、`packages[]{registryType,identifier,version,transport,environmentVariables}`、`remotes[]{type,url}`、`repository{url,source}`、`icons`、`_meta` | SSE 已废弃，2025-11 规范以 Streamable HTTP 取代；授权 OAuth 2.1 |
| **LangGraph** | `langgraph.json` | `dependencies`、`graphs`(name→`path.py:graph`)、`env`、`python_version`、`auth`、`store` | 部分字段官方页 404【未核实】 |
| **Flowise** | `.chatflow` 纯 JSON | `nodes[]{id,type,data:{type,node:{name,displayName,version,parameters}},position}`、`edges[]{source,sourceHandle,target,targetHandle}` | 无 manifest；凭据存 DB，3.1.4 导出已剥离变量值 |
| **Dify** | `manifest.yaml` + Provider YAML + DSL `.yml`【官方】 | `version`、`type`、`author`、`name`、`label`、`icon`、`resource.memory`、`permission.{tool,model,llm,endpoint,app,storage}`、`plugins.{tools,models,endpoints,agent_strategies}`、`meta.runner.{language,version,entrypoint}` | DSL：`kind: app`、`app.dependencies[]`、`workflow.graph.{nodes,edges,viewport}` |
| **BeeAI / A2A** | Agent Card JSON，`/.well-known/agent-card.json`【规范】 | `name`、`description`、`version`、`supportedInterfaces[]{url,protocolBinding,protocolVersion}`、`capabilities{streaming,pushNotifications,extensions}`、`defaultInputModes`、`defaultOutputModes`、`skills[]{id,name,description,tags,examples}`、`provider`、`securitySchemes`(基于 OpenAPI 3.2)、`securityRequirements`、`signatures` | v1.0 用 `supportedInterfaces` 取代顶层 `url`；`security` 已改名 `securityRequirements`；迁移期建议新旧 well-known 双发 |
| **OpenClaw** | `openclaw.plugin.json` + `package.json#openclaw` + `SKILL.md` frontmatter【官方】 | manifest：`id`、`configSchema`、`kind`、`activation`、`skills`、`mcpServers`、`dashboard`、`contracts`；package：`openclaw.extensions`、`runtimeExtensions`、`install.minHostVersion`；SKILL：`name`、`description`、`metadata`、`user-invocable`；策略：`plugins.allow/deny/entries.<id>.enabled` | `openclaw.plugins install --runtime --json` 可验证运行时注册（区分"冷 manifest 检查"与"真实加载"） |

**字段缺口分析（关键）**：把上述格式做并集后，以下运行时关键字段**在所有主流协议中均不存在**【规范】：

- 进程启停与重启策略（`restartPolicy`、`onCrash`）
- 资源限制（`cpu`、`memory`、`maxConcurrency`）
- 健康检查（`healthCheck.path/interval/timeout`）
- 端口仲裁（`port`、`portRange`、`exclusive`）
- 日志/追踪接入（`telemetry.endpoint`、`logLevel`）
- 成本与配额（`quota`、`budget`）

> 这解释了为什么"插件管理器"仍是空白：协议只描述"怎么调用"，不描述"怎么运行"。同目录 `plugin-manifest/manifest.schema.json` 草案若能补齐这些字段并覆盖上述六类格式，正好卡位。

### 2.2 进程生命周期管理

| 工具 | 启动 | 健康检查 / 恢复 | 端口 | 隔离与日志 |
|---|---|---|---|---|
| MCP Inspector | `command + args` spawn stdio 子进程；HTTP/SSE 连远端 | `connectionTimeout` 默认 30s、ad-hoc 15s；崩溃自愈【未核实】 | OAuth 回调 Web 6274 / CLI-TUI 6276，同端口仅一进程 | 密钥 keychain；网络日志 |
| LangGraph Studio | `langgraph dev` 本地启动；托管 UI 回连 | checkpointer 实现状态中断/恢复；健康检查【未核实】 | `127.0.0.1:2024`；被 Safari/Brave 阻断时用 `--tunnel` | 旧版 Docker Compose ≥2.22 |
| Flowise | 单 Node 服务，插件非独立进程 | 无公开设计【未核实】 | 默认 3000 | SSEStreamer 回推执行轨迹；可接 OTel/Prometheus |
| **Dify** | 独立 Go `dify-plugin-daemon`；Python 插件子进程经 STDIN/STDOUT | `PLUGIN_MAX_EXECUTION_TIMEOUT=600`、`PYTHON_ENV_INIT_TIMEOUT=120`；K8s 社区方案用 CRD + readiness 探针 + finalizer | 5002(GIN HTTP) / 5003(gnet 调试) | Marketplace 签名校验；nsjail/gVisor sandbox + SSRF proxy |
| BeeAI | `agentstack ui/list/run` 包装为 HTTP/A2A 服务 | 【未核实】 | 【未核实】 | Helm/K8s；OTel + GlobalTrajectoryMiddleware |
| **OpenClaw** | `onboard --install-daemon`；launchd/systemd 守护 + 自动重启 | hybrid reload 热替换插件实例；部分策略需重启；`beginClose()/stop()` 优雅关闭 + SQLite WAL checkpoint | `127.0.0.1:18789` | 插件同进程运行，视为可信代码；`plugins.allow` 白名单 |

**可复用模式**：① **独立守护进程**（Dify）比同进程插件（OpenClaw/Flowise）更安全，但带来进程编排复杂度；② **热重载 + 显式重启策略**（OpenClaw）是较好的折中；③ **Manifest 声明 + 运行时二次校验**（`--runtime` inspect）解决了"配置写了但没真的加载"的信任问题。

### 2.3 Agent 注册与发现协议

| 工具 | MCP | A2A / Agent Card | OpenAPI | 发现机制 |
|---|---|---|---|---|
| MCP Inspector | ● 原生：`initialize` 能力协商、`tools/resources/prompts/skills/list`、MCP Apps UI | ○【未核实】 | ○【未核实】 | 本地 catalog 配置 |
| LangGraph Studio | ◐ 平台侧提供 MCP endpoint（v1.0） | ◐ 平台侧提供 A2A 端点 | ○【未核实】 | `langgraph.json.graphs` + Assistants API 版本化 |
| Flowise | ◐ `Custom MCP` 节点（stdio/streamable HTTP + headers），工具列表需手动刷新 | ○ 仅 issue [#4283] | ○ | NodesPool 动态 require |
| Dify | ●● 双向：SSE/Streamable HTTP 接入外部 Server，也可发布为 MCP Server | ◐ 需 Nacos `A2A Discovery` + `A2A Server` 插件（含 `/.well-known/agent.json`） | ● OpenAPI 3.0/Swagger 导入为自定义工具 | Marketplace |
| BeeAI | ● 原生工具集成（含 OAuth） | ●● ACP 已并入 A2A，`A2AServer` / `A2AAgent` 适配器 | ◐ 间接 | Agent Card well-known |
| OpenClaw | ●● 双向（server + client） | ○【未核实】 | ○ | ClawHub 默认发现源 + VirusTotal 扫描 |

**关键差异**：MCP 管"Agent → 工具"，A2A 管"Agent → Agent"，二者互补而非竞争；OpenAPI 只描述 HTTP 契约。三者都**没有**覆盖"运行时实例"的注册（哪个进程、跑在哪、健康状态、资源占用）——这是注册维度最实质的空白。

### 2.4 数据端口暴露与可视化渲染策略

| 工具 | 暴露的数据 | 渲染策略 |
|---|---|---|
| MCP Inspector | tools/resources/prompts/skills、网络日志、结构化 JSON 结果 | 列表 + **JSON Schema 动态表单**（SchemaForm、enum picker）；CLI `--format json` + 退出码表（4=不可达、11=429） |
| LangGraph Studio | 图结构、每节点中间状态、threads/assistants、长期记忆 store、trace/dataset | 左侧图 + 输入配置，右侧输出/状态；状态可 pencil 编辑后 Fork；checkpoint 列表时间旅行；interrupt 暂停 UI |
| Flowise | nodes/edges JSON、SSE 执行轨迹 | ReactFlow 画布，连线即数据流；Traces 面板 |
| Dify | DSL graph、日志/反馈/标注/延迟/用量 | ReactFlow，`data.type` + `sourceHandle` 表达分支；30 天日志历史；可接 LangSmith/Langfuse |
| BeeAI | events、轨迹日志、OTel metrics | 事件可观测 + Web UI 测试/分享 |
| OpenClaw | `health`/`status`/`send`/`agent`/`system-presence` 请求；`agent`/`chat`/`presence`/`health`/`heartbeat`/`cron` 事件 | Control UI（Vite+Solid SPA，同端口 `:18789` 直连 WS），按 operator scope 授权渲染 chat/activity/nodes/devices/sessions/config/usage/插件 catalog |

**渲染模式归纳**：① 图结构渲染（LangGraph/Flowise/Dify）——适合展示控制流；② Schema 驱动表单（Inspector）——适合展示工具参数；③ 事件流面板（OpenClaw/BeeAI）——适合展示运行时状态。**三者尚未统一**：一个理想的运行时控制台应同时具备"拓扑 + 参数 + 实时状态"三层视图，并把跨 Agent 的 trace 串起来。

### 2.5 逐工具要点与用户痛点

**MCP Inspector** — 协议层最权威的调试器，但非运行时。【官方/社区】
痛点：OAuth/自定义 header 跨源不合规（#576 / #675 / #726）；连接挂起超时（#1858 / #2028）；复杂 schema `anyOf/oneOf` 导致无表单控件（#332 / PR #2137）；升级后命令失效（#326）；多端配置一致性（#3021）。以上 Issue 均在 `modelcontextprotocol/inspector` 仓库。

**LangGraph Studio** — 唯一提供"时间旅行"级状态调试的工具，但 UI 闭源、桌面版废弃。【官方/社区】
关注点：闭源 UI 与开源 runtime 的边界；localhost HTTP 被浏览器策略阻断需 tunnel；健康检查/崩溃自愈无公开设计。

**Flowise** — 已退场，但其失败原因本身就是重要结论。【官方】
2026-07-29 冻结开发 → 08-13 归档 → 08-31 EOL；最后版本 3.1.4（安全修复：MCP stdio 命令 allowlist、会话校验、导出剥离变量），09-10 曝光 6 个 High/Critical 公告且无补丁；Cloud 登录页 10-16 起无法解析。痛点历史：Agent 未调用 [#2557]（58 评）、UI 白屏 [#3583]、文档预览空白 [#5097]、缺流程版本化 [#2882]。

**Dify** — 四维度中综合最完整，代价是 16 容器部署复杂度。【官方/社区】
痛点：后端技术栈现代化 [#30269]、父子分块检索无结果 [#40680]、文件变量失效 [#40874]、流式输出卡顿 [#41556]、上下文压缩击穿前缀缓存 [#44826]。

**BeeAI** — 协议最规范（ACP→A2A），但平台化尚不成熟。【官方】
痛点：MCP 服务重启后 MCPTool 永不恢复 [#1889]、Anthropic 模型 400 错误 [#1887]、持久化 Memory 缺失 [#1708]；Agent Stack 395 开放 issue 值得警惕。

**OpenClaw** — 本地运行时的事实标杆，但同进程插件与状态膨胀是隐患。【官方/社区】
痛点：大插件捕获致 Gateway 阻塞数分钟 [#160959]、实时语音状态无界增长 [#116201]、agentDir 引导文件静默忽略 [#29387]、MCP 附件字节未转发 [#185765]。

### 2.6 社区共性痛点（跨工具，市场空白的直接证据）

1. **安装配置繁琐、静默失败**：GUI 与终端 PATH 不一致导致找不到 `npx`/`uvx`，配置错误常无提示【社区】
2. **端口冲突**：`EADDRINUSE` 需手工 `lsof`/`netstat` 排查【社区】
3. **崩溃无恢复**：遥测中出现一天内 `mcp_connection_lost` 172 次/54 用户；曾有 PID 误判导致自 SIGKILL【社区】
4. **重复进程破坏共享状态**：为 iframe 与 agent 各起一份 MCP 进程，状态分裂【社区】
5. **工具命名冲突**：两个 server 暴露同名工具时第二个被静默丢弃，可达性取决于加载顺序【社区】
6. **Agent 元数据不统一**：Agent Card 无顶层 id/url，字段随版本重命名（`url`→`supportedInterfaces`），冷启动仍需带外发现【规范/社区】
7. **跨 Agent 观测断裂**：A2A 调用使 trace 断裂为多段孤立 trace，无法归因成本与定位慢节点【社区】
8. **日志分散、错误信息晦涩**："Server disconnected" 类错误缺少定位线索【社区】

## 3. 差异化机会点

### 3.1 可复用的设计模式（建议直接借鉴）

| 模式 | 出处 | 借鉴方式 |
|---|---|---|
| **控制平面 + 多客户端** | OpenClaw Gateway（CLI/TUI/Control UI 共连 WS） | 一个本地守护进程统一状态，多前端消费；避免多进程状态分裂 |
| **独立插件守护进程** | Dify plugin daemon（Go + STDIN/STDOUT 子进程） | 插件故障隔离；配合超时、签名校验、对象存储 |
| **Manifest 声明 + 运行时二次校验** | OpenClaw `plugins inspect --runtime` | 区分"冷检查"与"真实加载"，解决配置漂移 |
| **热重载 + 显式重启策略** | OpenClaw hybrid reload | 配置编辑即生效，插件声明是否必须重启 |
| **checkpointer 状态恢复 / 时间旅行** | LangGraph | 崩溃恢复不止"重启进程"，而是恢复到某个状态检查点 |
| **事件总线 + OTel 观测** | BeeAI events / OpenClaw event 流 | 统一采集运行时事件，避免 trace 断裂 |
| **well-known 发现端点** | A2A `/.well-known/agent-card.json` | 低成本实现 Agent 自描述发现；迁移期新旧路径双发 |
| **能力协商** | MCP `initialize` | 注册时协商能力版本，避免字段重命名导致的不兼容 |

### 3.2 明确的市场空白（按四维度）

**① 插件发现 —— 空白：跨协议统一清单 + 冲突仲裁**
现状是六套格式各自为政，MCP Registry 只收 MCP server，ClawHub 只收 OpenClaw 插件，Dify Marketplace 只收 Dify 插件。**机会**：做一个"适配器层"，把六类清单归一为统一能力模型（同目录《插件与Agent互操作协议选型报告》已给出三层分工：发现层 → 打包层 → 调用层），并提供工具名冲突检测（解决痛点 5）。

**② 进程管理 —— 空白最大：声明式进程生命周期**
所有协议都不描述进程启停、健康检查、端口仲裁、资源限制、崩溃恢复（§2.1 字段缺口）。**机会**：在 manifest 中新增 `runtime` 段（`restartPolicy` / `healthCheck` / `port` / `resources` / `telemetry` / `quota`），由管理器负责端口分配与冲突检测、健康探活、崩溃自动拉起、状态检查点恢复。这直接命中痛点 1/2/3/4。

**③ Agent 注册 —— 空白：运行时实例注册**
MCP/A2A 注册的是"能力描述"，不是"活着的实例"。**机会**：在 Agent Card 之上增加运行时注册表（实例 ID、宿主、健康状态、版本、负载、成本），把 well-known 发现与动态实例注销结合，解决冷启动发现与状态漂移（痛点 6）。

**④ 数据可视化 —— 空白：拓扑 + 参数 + 实时状态三合一，且跨 Agent trace 串联**
现有工具各占一层：LangGraph 强在拓扑与状态，Inspector 强在 Schema 表单，OpenClaw 强在事件面板。**机会**：做统一运行时控制台——左侧拓扑、中间参数/清单、右侧实时健康与 trace，并把 A2A/MCP 跨调用链串成单一 trace（痛点 7/8）。

### 3.3 建议的产品切入点

**一句话定位**：*面向编码 Agent 生态的本地优先「插件/Agent 运行时控制台」——补上 MCP/A2A 协议不管的那一层。*

1. **不必重做画布**：Flowise 的退场说明低代码画布不再是卖点；应做"开发者可见、可调试、可治理"的运行时层。
2. **先做本地守护进程**：借鉴 OpenClaw Gateway，提供 CLI + Control UI，管理多种协议插件的进程生命周期；固定端口 + 端口仲裁表。
3. **Manifest 是核心资产**：以同目录 `plugin-manifest/manifest.schema.json` 草案为基础，补齐 §2.1 的六类运行时字段，并写 MCP / A2A / OpenAPI / Dify / OpenClaw 五个适配器。
4. **差异化护城河**：① 跨协议名称冲突检测；② 崩溃恢复 + 状态检查点；③ 跨 Agent 统一 trace。这三点现有六家全都不完整。
5. **商业模式警示**：Smithery/mcp.run 关停说明纯注册表/托管不成立；应绑定运行时治理（本地免费 + 团队版协作/审计/远程管理），参考 LangSmith 的席位制与 Dify 的工作区制。

### 3.4 风险与待核实项

- Flowise Cloud 是否已完全停止服务、OpenClaw 的 A2A 支持状态、LangGraph Platform 现行单价、BeeAI 平台健康检查机制均标记【未核实】，落地前需二次确认。
- OpenClaw 插件与 Gateway **同进程**运行，安全模型假设插件可信；若做第三方插件运行时，独立进程隔离应作为默认而非选项。
- A2A v1.0 字段重命名频繁（`url`→`supportedInterfaces`、`security`→`securityRequirements`），适配器需做版本兼容与双发。
- 同目录已有《插件与Agent互操作协议选型报告》与 Manifest Schema 草案，建议本报告 §3.2/§3.3 与其结论合并进入产品设计，避免重复造轮子。
